# RedRed — AI-консультант для ekt.kz

Прототип для покупателей ekt.kz: помогает найти электротехнический товар, проверить характеристики, наличие и документы, объяснить выбор аналога и добавить товар в корзину **только после подтверждения**. Корзина пока принадлежит прототипу, а не сайту ekt.kz.

FastAPI хранит гостевые сессии, аккаунты клиентов, каталог товаров ekt.kz, историю сообщений, избранное, вложения, предложения и корзины в PostgreSQL. Основной сценарий backend: найти товар по артикулу → создать предложение с количеством → явно подтвердить его → получить сохранённую корзину и ссылку `/cart`. Предложение само по себе корзину не меняет. Подтверждение заново проверяет цену и общий остаток в API ЕКТ; вся запись проходит одной транзакцией. Изменившаяся цена, недостаток товара или недоступность ЕКТ отклоняют подтверждение.

## Гость, клиент и авторизация

Чат, корзина и избранное доступны гостю после `POST /api/session`; регистрация для них не нужна. Аккаунты принадлежат этому приложению: выданный API каталога ЕКТ не предоставляет вход в существующие аккаунты ekt.kz. Две роли — `client` и `admin`; гость не является отдельной ролью. Публичная регистрация создаёт только клиента. Администратор входит отдельно через `/api/admin/session` по серверному `ADMIN_PASSWORD`; клиентская cookie не даёт доступа к админским маршрутам.

Контракт для клиентского фронтенда:

| Метод и путь | Тело / результат |
| --- | --- |
| `POST /api/session` | Создаёт гостя или возвращает текущую сессию: `csrf_token`, `expires_at`, `user` либо `null`. |
| `POST /api/auth/register` | `{email,password,name?}`; возвращает `user`, новый `csrf_token`, `expires_at`, `cart_merge_draft`. |
| `POST /api/auth/login` | `{email,password}`; возвращает тот же формат. |
| `GET /api/auth/me` | `{authenticated,user,csrf_token,expires_at}`; без входа значения пользователя и токенов равны `null`. |
| `POST /api/auth/logout` | Отзывает текущий вход; другие устройства остаются авторизованными. |
| `GET /api/favorites?limit=20&offset=0` | `{items,total}`, карточки загруженного каталога. |
| `PUT /api/favorites/{product_id}` | Добавляет в избранное; повтор не создаёт дубликат. |
| `DELETE /api/favorites/{product_id}` | Убирает из избранного текущего гостя или клиента. |
| `GET /api/auth/cart-drafts` | Сохранённые товары гостя, которым нужно подтверждение добавления в корзину аккаунта. |
| `POST /api/auth/cart-drafts/{id}/proposal` | Создаёт обычное предложение с проверкой актуальной цены и наличия; подтверждение выполняется через `/api/cart/proposals/{id}/confirm`. |

Перед регистрацией и входом фронтенд вызывает `POST /api/session`. Изменяющие запросы отправляются с cookie, допустимым `Origin` и `X-CSRF-Token`. После входа или регистрации нужно заменить CSRF-токен полученным значением, заново загрузить корзину, избранное и историю и переподключить WebSocket. После выхода вызывается `POST /api/session`, чтобы продолжить работу новым гостем. На другом устройстве клиент видит данные того же аккаунта. Выход и истечение cookie не удаляют данные зарегистрированного клиента.

При регистрации текущие гостевые данные закрепляются за аккаунтом. При входе в существующий аккаунт история и избранное сохраняются; конфликт корзин разрешается через сохранённый черновик и обычное явное подтверждение добавления. Регистрация и вход могут вернуть `AUTH_BUSY`, если ещё обрабатывается сообщение: повторите запрос после его завершения. Подтверждение email и восстановление пароля пока не реализованы.

Одновременная подготовка одного черновика защищена блокировкой PostgreSQL: второй запрос возвращает `409 DRAFT_PREPARING`, его можно повторить. Повторная подготовка уже подтверждённого черновика возвращает прежнее предложение и не добавляет товары второй раз.

## Синхронизация каталога и админка

Задайте серверный `ADMIN_PASSWORD` и откройте `http://localhost:8000/admin/catalog` после запуска API. Страница позволяет обновить уже загруженные карточки, начать полный обход каталога ЕКТ, запросить остановку, видеть фактические счётчики, ошибки и историю. `ADMIN_ORIGIN` должен точно совпадать с origin этой страницы (по умолчанию `http://localhost:8000`). Пароль передаётся только при входе, не хранится во фронтенде и не попадает в URL. При пустом `ADMIN_PASSWORD` вход и защищённый API отвечают `ADMIN_NOT_CONFIGURED`. Админская cookie отделена от гостевой, имеет HttpOnly и срок 8 часов; изменяющие запросы требуют её CSRF-токен и допустимый Origin. При HTTPS задайте `SECURE_COOKIE=true`.

Та же страница доступна по `/admin`: разделы показывают реальные показатели PostgreSQL, диалоги гостей и клиентов, синхронизацию каталога и настройки. `GET /api/admin/dashboard` возвращает счётчики клиентов, активных гостей, диалогов, сообщений, товаров каталога, строк корзин и подтверждённых предложений. Это не отчёт об оплаченных заказах. `GET /api/admin/chats?kind=all|guest|client&q=&limit=20&offset=0` возвращает список диалогов, `GET /api/admin/chats/{session_id}/messages?limit=50&offset=0` — сообщения выбранного диалога, начиная с новых. Просмотр чужих диалогов доступен только администратору.

`GET /api/admin/settings` читает настройки; `PATCH /api/admin/settings` изменяет только переданные поля: `catalog_sync_enabled` (boolean), `catalog_sync_interval_seconds` (60–86400), `catalog_sync_concurrency` (1–2), `catalog_sync_timeout_seconds` (1–60). Значения сохраняются в PostgreSQL и имеют приоритет над стартовыми настройками окружения. Через эти маршруты нельзя получить или изменить пароли, ключи API и строку подключения к БД.

Изменения применяются сразу в обслужившем запрос процессе, остальные процессы подхватывают их в течение пяти секунд. Уже запущенное обновление сохраняет свои исходные таймаут и параллельность. Выключение расписания не отменяет текущую работу; для этого есть отдельная кнопка остановки. Ручное обновление остаётся доступным при выключенном расписании.

Параметры в `.env.example`: `CATALOG_SYNC_ENABLED=true` включает автоматический полный обход при запуске сервера, если доступны учётные данные ЕКТ и наступило время очередного запуска. Без прежних запусков он начинается сразу; затем следующий старт планируется через `CATALOG_SYNC_INTERVAL_SECONDS=900` после завершения предыдущего. `CATALOG_SYNC_ENABLED=false` отключает расписание, но оставляет ручной запуск в админке при настроенных учётных данных. `CATALOG_SYNC_CONCURRENCY=2` ограничивает параллельные запросы карточек, `CATALOG_SYNC_TIMEOUT_SECONDS=10` — время отдельного запроса к источнику. Полный обход заканчивается на пустой или повторённой странице, отсутствии новых ID либо неполной последней странице; при ошибках отдельных карточек результат отмечается как частичный, а не успешный. Только один обход выполняется одновременно благодаря блокировке PostgreSQL. На остановке сервера текущая работа прерывается с сохранением статуса.

Для точечной проверки маршрутов админки без запросов к ЕКТ задайте `CATALOG_SYNC_ENABLED=false` в окружении и выполните `Set-Location 'C:\Users\Daniyar\Documents\HackAlem\hack-63e62cb7-redred'; & 'C:\Users\Daniyar\Documents\HackAlem\hack-63e62cb7-redred\backend\.venv\Scripts\python.exe' -m unittest backend.tests.test_admin_sync -v` после миграции схемы. Тест подставляет тестовую задачу синхронизации и проверяет вход, права, CSRF, запуск, повторный запуск и отмену. Он не измеряет длительность полного обхода ЕКТ.

На PostgreSQL прошли шесть точечных проверок админки и синхронизации, включая восстановление прерванной задачи, отмену, защиту от параллельных запусков и перезаписи свежих данных старыми. Также 23 сентября 2026 года через настоящий API админки запущено обновление 21 сохранённой карточки из ЕКТ: все обновлены без ошибок примерно за 3 секунды. Запуск вернул HTTP 202 за 172 мс, чтение каталога во время обновления заняло 31 мс, повторный запуск отклонён с HTTP 409. Это измерение одной ограниченной проверки; полный обход каталога ЕКТ не запускался.

Целевой frontend обращается к FastAPI по `/api` и WebSocket; прокси в Vite пока не настроен. Backend хранит сессии, ограниченную выборку каталога, сообщения, предложения и корзины в PostgreSQL. Свежие детали, цену и остаток он читает из ekt.kz по Basic Auth. AI получает только инструменты чтения и возвращает предложение; корзину меняет лишь серверный обработчик подтверждения. Секреты остаются на backend.

`backend/data/demo_products.json` содержит 21 выбранную карточку из проверки API 23 сентября 2026 года. Это начальная выборка, а не полный каталог; цена и остаток в ней не считаются актуальными. Для четырёх проверенных товаров настроены единица и шаг продажи. `backend/data/purchase_terms.json` содержит подтверждённые сведения об оплате и доставке с предупреждением о противоречивых порогах бесплатной доставки. Источники: [API каталога](https://ekt.kz/api/products), [детальная карточка](https://ekt.kz/api/products/detail?id=515291), [условия покупки](https://ekt.kz/checkout-delivery/).

Технологии: Python 3.12+, FastAPI, SQLAlchemy, asyncpg, PostgreSQL 17, httpx, React, TypeScript, Vite и OpenAI Responses API (`gpt-6-sol`). `compose.yaml` поднимает только PostgreSQL; Nginx и Docker-запуск всего приложения ещё не добавлены. Запускайте эти команды на тестовой БД: `--prepare-db` создаёт схему и импортирует демовыборку; первый скрипт создаёт собственную сессию и удаляет её после проверки. `smoke_service` проверяет несколько потоковых ответов с локальными карточками. `smoke_attachments` загружает публичное JPEG-изображение товара ekt.kz, создаёт тестовый PDF в памяти и проверяет оба файла через чат. `smoke_ws` проверяет реальный поток WebSocket, итоговый текст и карточку товара. Скрипты читают локальный `.env`, сервер по-прежнему использует окружение процесса. Если Windows не позволяет занять порт 5432, для отдельной тестовой БД можно использовать:

```powershell
docker run --detach --name redred-ai-check-db --publish 127.0.0.1:25432:5432 --env POSTGRES_DB=hackalem --env POSTGRES_USER=hackalem --env POSTGRES_PASSWORD=hackalem postgres:17-alpine
$env:DATABASE_URL = 'postgresql+asyncpg://hackalem:hackalem@127.0.0.1:25432/hackalem'
```

AI делает максимум два вызова модели и получает до трёх свежих карточек за сообщение. После вызова инструментов `emit` передаёт части текстового поля из потокового ответа OpenAI; итоговый структурированный результат проверяется отдельно. Для ответа без инструментов текст пока приходит одним событием. Таймаут обычного сообщения остаётся 8 секунд, вложений — 20 секунд. DOCX/XLSX разбираются локально с ограничением объёма; формулы не исполняются. JPEG и PDF передаются модели. Сквозная проверка JPEG дала описание фото без точной привязки к артикулу; из PDF модель извлекла артикул и получила карточку из EKT. Контент вложений отправляется в OpenAI; `store=false` отключает сохранение Responses, но не является обещанием отсутствия всех журналов у провайдера.

Использованные материалы OpenAI Docs: [вызов инструментов](https://developers.openai.com/api/docs/guides/function-calling), [структурированные ответы](https://developers.openai.com/api/docs/guides/structured-outputs), [входные файлы](https://developers.openai.com/api/docs/guides/file-inputs).

## Языки, нехватка количества и долгий диалог

Чат принимает `language: ru | kk | en`. Явный выбор в запросе или просьба «на казахском», «English please», «Қазақ тілінде жауап бер» сохраняется в сессии. При отсутствии выбора используется простое определение языка; для неоднозначной смешанной фразы надёжнее явно передать `language`. Подтверждения `да, добавь`, `иә қосыңыз`, `yes add it`, `иә добавь` распознаются сервером целиком. Отдельное `да / иә / yes`, условие «добавь, если…» и фраза с новым количеством ничего не подтверждают. Отмена предложения также поддерживается; состав корзины при отмене предложения не меняется.

При нехватке количества AI сообщает проверенный доступный остаток и предлагает изменить количество или подобрать аналог. Если остаток уменьшился именно к подтверждению, чат сохраняет ответ с причиной отказа и `warnings: ["INSUFFICIENT_STOCK"]`; корзина не меняется. Старое предложение отменяется, новое количество требует нового предложения и подтверждения. Отказ при подтверждении кнопкой остаётся HTTP 409; причина также сохраняется в контексте AI для следующего сообщения. Фронтенду нельзя считать HTTP 200 чата признаком покупки: нужно проверять `proposal`, `cart`, `cart_url` и `warnings`.

Полная история хранится в PostgreSQL, модели сразу передаются последние 12 завершённых сообщений (до 12 000 символов). `Session.state` сохраняет последние ID товаров, запрошенное количество и последний отказ корзины, без копирования устаревших цен/остатков. Инструмент `search_history` ищет только внутри текущей сессии, возвращает до 8 сообщений/8 000 символов и перечитывает связанные товары из каталога. Это ограниченный поиск по словам, а не неограниченная память всех фактов. Исторический текст не разрешает покупку и не подтверждает актуальность цены.

Гостевая сессия живёт 24 часа по умолчанию; срок задаётся `SESSION_HOURS` при создании, автоматически не продлевается. Пока действуют cookie и сессия, перезапуск backend не удаляет историю. По истечении срока доступ прекращается; физическая очистка выполняется командой `python -m backend.cleanup`. Для нескольких дней можно установить, например, `SESSION_HOURS=168` до создания новых сессий. История между устройствами и восстановление после потери cookie без авторизации не реализованы.

Проверки этой доработки: 21 тест AI/языков/чата/корзины прошёл. Реальные OpenAI/EKT: казахское предложение, английский аналог, смешанная фраза с завышенным количеством и поиск товара за пределами последних 12 сообщений — 4/4, 4,8–6,3 секунды в последнем прогоне. Отчёт: `ai/reports/backend-multilingual-live.json`; результаты не являются нагрузочным тестом. Первый прогон выявил неуспешные поиск/получение карточки, поэтому единичный успешный прогон не гарантирует постоянную доступность внешнего API.

## Ограничения

- Корзина принадлежит прототипу: она не изменяет корзину ekt.kz, не резервирует товар и не оформляет заказ. Предоставленный партнёром API доступен только для чтения. Пункт кейса о переходе к оформлению на ekt.kz требует отдельной интеграции.
- Frontend-чат, `/cart` и развёртывание для судей ещё не завершены. Для вложений проверены локальное извлечение DOCX/XLSX и сквозные запросы JPEG/PDF с моделью. По одному фото точный артикул надёжно определить не удалось; требуется уточнение клиента. Старые DOC/XLS не поддерживаются.
- Поиск ограничен импортированной выборкой. Наличие указано по общему остатку без выбора склада. Для неизвестной единицы или шага продажи покупка блокируется.
- Публичные условия доставки содержат два разных порога бесплатной доставки; точное условие нужно подтвердить у продавца. Единая схема сертификатов для всего каталога не установлена.
- URL развёрнутой версии пока отсутствует.

## Дополнительные проверки backend

`GET /api/products` принимает `q`, точный `article`, `category`, `in_stock=true`, `sort=relevance|price_asc|price_desc`, `limit` до 20 и `offset`. Фильтры `series`, `current` и `breaking_capacity` можно повторять; внутри одного фильтра значения объединяются по ИЛИ, разные фильтры — по И. Нужны точные значения из карточек, например `series=DRX125%20MT`, `current=50%20%D0%90`. Серия DRX125 MT или DRX250 MT определяется только по проверенному пути страницы товара. Категории `Силовые автоматические выключатели`, `Модульные автоматические выключатели`, `Коробки`, `Спецпредложения` тоже следуют пути страницы; неизвестный путь остаётся `Каталог ЕКТ`. Ответ поиска: `{items,total,catalog_scope}` с `catalog_scope="demo_subset"`.
